# Hosted demo on Render (free tier, login-protected, synthetic data)

**Step-by-step deployment instructions are in the [README](../README.md#deploy-the-demo-on-render-free-tier).** This page explains how the deployment works, how it is protected, and what to expect from the free tier.

**What the demo is:**
- **Synthetic data only.** It is generated inside the app; the demo refuses any other import, and there are no connections to company systems.
- **No AI calls.** The AI provider is off.
- **No credentials in Git.**

**What it is not:** the pilot. Real data, Microsoft sign-in and the integrations remain open ([INTEGRATION_CHECKLIST.md](INTEGRATION_CHECKLIST.md)).

## How it is deployed

**One web service, built from the root `Dockerfile`:**
1. The first build stage runs `npm ci` and `npm run build` in `frontend/`.
2. The second stage installs `backend/requirements.txt` and copies the built app into `/app/frontend/dist`.
3. The container starts `python -m app.cli serve`, which does the following in order:
   - checks the configuration and refuses to start if it is unsafe;
   - runs the database migrations;
   - creates or refreshes the synthetic demo data if it is missing or older than 24 hours;
   - starts the server on **`0.0.0.0:$PORT`**. Render sets `PORT`, which defaults to 10000.

**Routing on one URL:**
- **The frontend and backend share one URL.** The React app calls the API with relative `/api/...` paths, so no API address needs configuring.
- **Every other path** that is not a file serves `index.html`, so refreshing a page such as `/customers/JC/…` works.
- **The health check**, `/healthz`, checks the database connection and returns `{"status":"ok"}` with no data.

**One free PostgreSQL 16 database:**
- Render injects its connection string as `DATABASE_URL`; the app converts `postgresql://` to its psycopg driver automatically.
- `ipAllowList: []` keeps the database off the public internet.

## How it is protected

- **Login gate on everything.** Every page, static file and API call requires signing in on `/login` with `DEMO_ACCESS_USER` / `DEMO_ACCESS_PASSWORD`, which come only from Render's environment settings.
  - Pages without a session redirect to `/login` and return to the requested page after signing in.
  - API calls without a session get `401 {"error":{"code":"login_required"}}`.
  - Only `/healthz` is open.
- **Sessions:**
  - A signed, HttpOnly, SameSite=Lax cookie is used, marked `Secure` over HTTPS. It lasts 12 hours (`DEMO_SESSION_HOURS`).
  - Cookies are signed with `SESSION_SECRET` (generated by Render) combined with the current credentials. Changing the username or password therefore signs everyone out immediately.
  - **Salir / Sign out** in the header ends the session.
- **Scripts** may send the same credentials as HTTP Basic authentication. The app never sends a Basic challenge, so browsers always see the login page rather than their own prompt.
- **Wrong passwords are throttled:** 20 failures from one address within 10 minutes block further attempts for 10 minutes.
- **Safe redirects:** after sign-in the app only redirects to paths on the same site, never to another domain.
- **Behind the login, demo-user switching is available by design.** Anyone who can sign in can act as any demo user (Ana, Elena, Admin…).
- **Fail-closed configuration.** `APP_ENV=demo` refuses to start if any of these holds:
  - the username is missing or shorter than 3 characters, or the password is missing or shorter than 16 characters;
  - `AUTH_MODE` is not `demo`;
  - AI is enabled;
  - live or inbox imports are configured;
  - local development database credentials are used.
- **Synthetic data only.** The importer accepts only `data_classification=synthetic`.
- **Not indexed:** responses carry `X-Robots-Tag: noindex`.

## Free-tier behaviour

| Topic | What happens |
|---|---|
| **Cost** | Both resources use the `free` plan in `render.yaml`. If Render shows a paid plan or asks for payment when you apply the Blueprint, stop. |
| **Sleeping** | The free web service sleeps after 15 idle minutes. The next visit wakes it (about a minute, including migrations and, if needed, a data refresh). The background refresher only runs while the service is awake; on waking, stale data is regenerated before the server starts. |
| **Database expiry** | A free database expires 30 days after creation (with a grace period before deletion). To continue: delete it, run **Manual sync** on the Blueprint to create a new free database, and redeploy the web service. The demo data is recreated automatically; nothing real is lost. |
| **Daily reset** | Synthetic data regenerates once a day (around 06:00 Madrid time while awake, or on the next start). Actions recorded during a demo are cleared then. Restarts and redeploys on the same day keep the data. |
| **Shared state** | All visitors share the same demo users and see each other's recorded actions until the next reset. |

## Sharing with colleagues

- Send the URL and the credentials separately, for example the URL in the invite and the password in a direct message.
- After the demo period, change the password (web service → **Environment**). Everyone is signed out.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| *Empty build command; skipping build* / *Publish directory … does not exist!* | The service was created as a **Static Site** (no server, so no login gate or API). Delete it and use **New → Blueprint** with `render.yaml`. |
| Page says *"La API no está disponible en esta dirección"* | The interface is being served without its server (static hosting). Same fix. |
| Deploy fails with "Refusing to start: … DEMO_ACCESS_PASSWORD … / DEMO_ACCESS_USER …" | Credentials missing or too short. Set them under **Environment** and save. |
| First page load takes about a minute | The free service was asleep. This is expected. |
| Health check failing, logs mention the database | The free database expired or is unavailable. See *Database expiry* above. |
| Signed out unexpectedly | The session lasted 12 hours, or the credentials or `SESSION_SECRET` changed. |
